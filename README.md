# DemoMed Help Center

A [Docusaurus](https://docusaurus.io/) documentation/FAQ site with [Pagefind](https://pagefind.app/) search, for **DemoMed** — a fictional telehealth SaaS platform for clinics (dark/starfield theme, Inter font, blue-cyan gradient accents). The content walks through a physician configuring their clinic (video visits, scheduling, patient records, billing, HIPAA compliance, etc.).

## Requirements

- Node.js 20+

## Local development

```bash
npm install
npm start
```

This starts a hot-reloading dev server at `http://localhost:3000/wiki-demo/`.

> **Note on search in dev mode:** Pagefind indexes the final static build, not the dev server, so the `/search` page will show a "search index not found" message under `npm start`. To try search locally, build and serve the production site instead (below).

## Production build + search index

```bash
npm run build
```

`npm run build` runs `docusaurus build` and then automatically runs `pagefind --site build --output-subdir pagefind` as a `postbuild` step, generating a search index at `build/pagefind/`. The `/search` page (`src/pages/search.js`) loads `pagefind-ui` client-side from that folder.

To try the fully built site, including search, locally:

```bash
npm run build
npm run serve
```

## Languages (i18n)

The site is bilingual — **Romanian (default, served at `/`)** and **English (served at `/en/`)** — with a locale switcher in the navbar. `npm run build` builds both locales automatically (no extra flags needed); Pagefind then indexes both, auto-detects the two languages from each page's `lang` attribute, and the search page filters results to the current locale automatically.

Romanian is the default locale, so its content is the "raw" source:

- Romanian doc content lives directly in [`docs/`](./docs/) (including `_category_.json` sidebar category metadata).
- English doc content is the override, living in [`i18n/en/docusaurus-plugin-content-docs/current/`](./i18n/en/docusaurus-plugin-content-docs/current/), mirroring the `docs/` folder structure file-for-file.
- English sidebar **category labels/descriptions** are translated via [`i18n/en/docusaurus-plugin-content-docs/current.json`](./i18n/en/docusaurus-plugin-content-docs/current.json) — Docusaurus's autogenerated sidebar reads category metadata from the default locale's `_category_.json` only, so a localized `_category_.json` inside the `i18n/en/...` folder is *not* picked up; the `current.json` translation-key mechanism is what actually works.
- Other UI strings (navbar, footer, theme, the homepage/search page) for Romanian are already the config/component defaults, with an **English override** where needed (currently none are needed beyond the categories above, since the English text used in `docusaurus.config.js` and the `<Translate>` defaults in `src/` already reads as plain English).
- The Romanian UI overrides used while English was still the default locale are preserved in [`i18n/ro/code.json`](./i18n/ro/code.json) and [`i18n/ro/docusaurus-theme-classic/`](./i18n/ro/docusaurus-theme-classic/) — these are no longer required for Romanian's own rendering (Romanian is the baseline now) but are harmless to keep and would matter again if the default locale ever changes back.
- Adding a new doc page in Romanian and want it in English too? Run `npm run write-translations -- --locale en` to pick up any new translatable strings (it won't overwrite existing translations), then add the matching file under `i18n/en/docusaurus-plugin-content-docs/current/`. Headings that other pages link to by anchor (e.g. `#roles-overview`) need an explicit `\{#same-id}` suffix in the English heading too, so the anchor stays stable even though the heading text is translated.

## Deploying to GitHub Pages

`docusaurus.config.js` is already pointed at `andrast0th/wiki-demo` (`url`, `baseUrl`, `organizationName`, `projectName`, and the GitHub links). If you fork this to a different account/repo, update those values first.

### Option A — GitHub Actions (recommended)

This repo includes [`.github/workflows/deploy.yml`](./.github/workflows/deploy.yml), which builds the site (including the Pagefind index) and deploys it using GitHub's official Pages Actions on every push to `main`.

1. Push this repo to GitHub.
2. In the repo, go to **Settings → Pages** and set **Source** to **GitHub Actions**.
3. Push to `main` (or run the workflow manually from the **Actions** tab). The site will be published at `https://andrast0th.github.io/wiki-demo/`.

### Option B — `docusaurus deploy` (classic `gh-pages` branch)

```bash
GIT_USER=andrast0th npm run deploy
```

This builds the site (including the Pagefind postbuild step) and pushes the `build/` output to a `gh-pages` branch using [`docusaurus deploy`](https://docusaurus.io/docs/deployment#deploying-to-github-pages). If you use this option, set **Settings → Pages → Source** to **Deploy from a branch → `gh-pages`** instead of GitHub Actions.
